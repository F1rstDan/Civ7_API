# Doc Format

Civ7 API 文档统一排版规范。模板文件在 `assets/api-page-template.md`。

## 工作流

根据用户意图选择对应流程：

| 意图 | 流程 |
|------|------|
| 新建文档 | 复制模板 → 填充内容 |
| 审查存量文档 | 读取目标文件 → 按检查清单逐项对照 → 输出问题报告 |
| 整改存量文档 | 读取目标文件 → 按检查清单修复 → 写回文件 |

## 文档结构（必须按顺序）

```
1. frontmatter（title）
2. H1 标题
3. 一句话定位
4. 快速示例
5. H2 方法列表（表格 + <API> 触发器）
6. H2 子对象/子系统（可选）
7. H2 常用枚举（可选）
8. H2 GameInfo 关联表（可选）
9. H2 相关全局对象（可选）
10. 来源标注（斜体 footer）
11. <API> 弹窗内容块（全部放页面最底部）
```

## 格式规范

### 命名
- 文件名：小写英文 + 连字符，如 `gameplay-map.md`
- frontmatter：`title: 英文名 中文名`
- H1：`# 英文名 中文名`

### 代码块
- 统一 ` ```javascript ` 围栏，必须闭合
- 代码块内首行写 `// 来源 xxx.ltp` (源文件有.js或.ltp)
- 页面末尾写 `*来源：xxx.ltp*` (源文件有.js或.ltp)

### 弹窗标签

**触发器**（方法总表中）：
```markdown
| <API>Camera.lookAtPlot</API> | iX, iY | `void` | 说明 |
```
- `<API>` 内**不加反引号**，textContent 即为 id
- id 格式：`对象.方法名`

**内容块**（页面最底部）：
````markdown
<API id="Camera.lookAtPlot" title="Camera.lookAtPlot(iX, iY)">

**说明**: 一句话说明。

| 参数名 | 类型 | 说明 |
|------|------|------|
| iX | `int` | X 坐标 |
| iY | `int` | Y 坐标 |

**返回值**: `void`

**使用示例**:

```javascript
Camera.lookAtPlot(10, 20);
```

**来源**: Camera.ltp - SomeFunction

</API>
````

内容块内部顺序：说明 → 参数表 → 返回值 → 使用示例（可选） → 来源

## 大型对象拆分策略

当对象包含大量子系统时，采用 **主文件 + 独立子系统页**：

**主文件保留**：入口 API、子系统总览表、高频子系统摘要、链接

**独立子系统页适用**：API 超过 8 个方法、有独立枚举/GameInfo 表、被多个上游引用

**不拆分**：API 少于 5 个方法、仅服务于父对象

## 检查清单

审查或整改时逐项对照：

- [ ] 有 frontmatter（title 字段）
- [ ] H1 格式正确（# 英文 中文）
- [ ] 有一句话定位
- [ ] 有快速示例代码块
- [ ] 方法表使用 `<API>` 触发器（非 backtick）
- [ ] `<API>` 内无反引号
- [ ] 所有代码块标注 ` ```javascript `
- [ ] 所有代码块已闭合
- [ ] 代码块内有 `// 来源 xxx.ltp` 注释
- [ ] 页面末尾有 `*来源：xxx.ltp*`
- [ ] `<API>` 内容块放在页面最底部
- [ ] 内容块包含：说明、参数表、返回值、来源
- [ ] 大型文件（>350 行）是否需要拆分

## 新建文档流程

1. 读取 `assets/api-page-template.md`
2. 复制为目标文件名
3. 替换所有占位符（SomeAPI、xxx.ltp 等）
4. 按实际 API 填充方法表和内容块

## 审查/整改流程

1. 读取目标文件
2. 逐项对照检查清单
3. 输出问题列表（审查）或直接修复（整改）
4. 整改时保持现有内容不变，只调整结构和格式
