`doc_type`分类决策树：
- `object`（从object-api改名）
    - 展示一个全局对象的方法和属性？
    - 简单型：只有 Manager（如 Camera）
        - 特征：单一对象。
    - 标准型：Manager + Entity（如 Cities + city）
    - 复杂型：Manager + Entity + 子系统需拆分（如 Players）
        - 特征：有明确的全局入口对象，有 `get()` 获取实例，实例上有属性和子系统。
- `system`（从system-topic改名）
    - 解释一个游戏系统，涉及多个对象？
    - 比如：外交系统，科技文化。
    - 特征：跨多个对象的游戏系统。
- `data`（从reference改名）
    - 纯数据/事件列表/常量/枚举？
    - 比如：`events`、`game-info`等等。
    - 特征：静态参考。
- `other`（从ui-api改名）
    - 和游戏本体关系较低？
    - 比如： （UI、本地化、音频、调试、网络、社交、手柄输入）
    - 比如：`Component`、`Audio`、`Locale`等等。
    - 特征：非游戏内系统。
- `generated`（从generated-reference改名）
    - 脚本自动生成？
    - 比如：`constants`等等。
    - 特征：不可手动编辑，由脚本生成。
